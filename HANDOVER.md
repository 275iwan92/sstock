## 3. Yang sudah ada
- **Master:** Barang dua tingkat: **produk** (`products`, kode tetap `{AWALAN KATEGORI 3 KARAKTER}-{URUT 4 DIGIT}` lewat `Product::nextCode`, tanpa tanggal; parameter harga / titik pesan ulang / lead time hanya di sini, diteruskan ke batch oleh `Product::propagate`) dan **batch** (`items`: satu per tanggal kedaluwarsa, kode `{kode produk}-{YYMMDD}`, dibuat otomatis oleh Penerimaan / Saldo Awal lewat `Product::batchFor`; stok dan biaya rata-rata per batch). Semua pengguna boleh menambah barang, Supervisor mengubah parameter. Penerimaan memilih produk + tanggal kedaluwarsa; Pengeluaran memilih batch (daftar FEFO, kelebihan jumlah menyambung ke batch berikutnya, memilih batch lebih jauh hanya diperingatkan). Titik pesan ulang dihitung PER PRODUK dari stok tersedia (batch belum kedaluwarsa; `SSTOCK_REORDER_EXCLUDE_DAYS` menambah jendela hampir-kedaluwarsa); `reorder_orders` per produk (catatan pemesanan sederhana, bukan PO: supplier, jumlah dalam satuan stok, tanggal, ref + catatan opsional; kolom baru boleh kosong untuk baris lama; ditutup hanya bila jumlah diterima (alokasi FIFO dari Penerimaan terkonfirmasi sejak tanggal pesan, `ReorderOrders::reconcile`) memenuhi jumlah dipesan; penerimaan sebagian = "Diterima sebagian", tetap terbuka; pesanan lama tanpa jumlah tetap ditutup penerimaan pertama; "Tutup Pesanan" manual (`close_reason='manual'`) untuk pesanan yang tak akan dipenuhi penuh; lead time dihitung sampai penerimaan PERTAMA (`first_received_at`), pesanan yang sudah menerima barang tidak ditandai terlambat lagi; migrasi `add_receipt_progress_to_reorder_orders`; lead time otomatis + perkiraan tiba + saran titik pesan ulang lewat `LeadTimes` / engine DevLib `LeadTime`, hanya keterangan dan saran), Kategori (awalan 3 karakter), Lokasi Penyimpanan (`items.location` menyimpan kodenya), Supplier (kontak + wilayah `geo_*` salinan tmerp), Satuan + konversi global (`UnitConverter`, hanya cadangan) + **Satuan masuk per barang** (`product_units`, `ProductUnits`: faktor ke satuan stok barang itu, didahulukan dari konversi global; aturan ubah: siapa pun membuat / memperbaiki yang belum dipakai di dokumen terkonfirmasi, yang sudah dipakai hanya hak UOM = Supervisor, selain itu 403), Departemen, Penerima (dropdown di dokumen + baris "Penerima baru"/"Departemen baru" membuka dialog tambah cepat `docs/quick-add.blade.php`, dialog dipindah ke `<body>`).
- **Transaksi (`docs/{type}`, 4 jenis):** Saldo Awal, Penerimaan (boleh satuan stok atau Satuan masuk barang itu; hasil konversi tampil langsung di baris, jendela "Faktor satuan belum ada" membuat Satuan masuk milik barang), Pengeluaran dan Penyesuaian (selalu satuan stok, tanpa pemilih satuan). Siklus: Draf (bisa Hapus, belum ke stok) > Confirm (diproses; tanggal/jam = saat Confirm) > Cancel (lihat aturan 6; stok dibalik lewat baris pembalik `stock_movements.reversal_of`, baris asal tidak diubah). Penyesuaian: Draf > Confirm (diajukan) > Approve Supervisor (baru ke stok) / Reject. Status `cancel_pending` = pengajuan pembatalan menunggu Supervisor (di form tampil lewat tahap persetujuan DevLib). Penerimaan yang dibatalkan membuka lagi pemesanan ulang yang ditutupnya. Departemen + Penerima ada di Penerimaan, Pengeluaran, Penyesuaian (opsional kecuali Penerima di Pengeluaran; nama disalin ke kolom teks dokumen; departemen kosong = bawaan penerima).
- **Stok Opname (penghitungan fisik rutin, modul `SO`, menu Transaksi):** `stock_counts` + `stock_count_lines` (snapshot stok sistem + biaya rata-rata per batch saat mulai), logika di `App\Services\StockCounts`, layar `StockCountController` (`stock-counts.*`), cetak lewat `App\Support\StockCountPrint` (Lembar Hitung dan Berita Acara, `x-dl::print-sheet`). Alur: Mulai (Supervisor) > Sedang dihitung (input massal `x-dl::lookup-grid` simpan otomatis; kosong = belum, 0 = kosong, Tidak dihitung + catatan) > Selesai hitung > Tinjau (hitung ulang, alasan wajib di atas ambang) > Setujui = SATU Penyesuaian approved lewat `StockDocuments::recordCountAdjustment` + `StockLedger::post`, stok baris selisih harus masih sama dengan snapshot. Hanya satu opname berjalan. **Kunci transaksi:** satu penjaga di `StockLedger` (`post` dan `reverse`, `StockCount::lockingNow()`); Setujui menulis status Selesai lebih dulu supaya posting Penyesuaiannya lolos. Layar tinjau memuat ulang halaman setelah simpan lewat `resources/js/app.js` (butuh `npm run build`). Migrasi: `create_stock_counts_tables`, `give_stock_count_to_groups` (grup yang RW di ADJ atau RCV mendapat SO RW), `add_lock_audit_to_stock_counts` (Supervisor bisa Kunci lagi), `add_entry_audit_to_stock_count_lines` (`entered_by/at`, `rev`: penjaga lunak dua penginput, 409 + alasan = menimpa), `create_constants_table` (key/value bersama; jadwal opname di `opname.*` lewat `App\Support\Constants`). **Jadwal dan pengingat Beranda:** `App\Services\CountSchedule` (Bulanan tanggal / akhir bulan, Mingguan hari; berikutnya dari opname Selesai terakhir), `partials/count-reminder`, lencana menu di `Menu`.

## 4. Catatan teknis penting
- Alat: heredoc Python di bash sering gagal bila isinya berisi `\` atau tanda kutip, pakai tool Write/Edit atau berkas skrip di scratchpad; tinker satu baris dengan `$` gagal, pakai berkas skrip (`php artisan tinker <berkas.php>`). Peringatan CRLF git tidak berbahaya.
- Widget DevLib: select = `[data-dl-select]` + input tersembunyi `[data-dl-value]`; modal dibuka dengan class `is-on` pada `[data-dl-modal-id]`; validasi form menghitung `.dl-field__req` yang kosong; Back komponen memakai `history.back()` kecuali `DL_BACK_HISTORY=false`.
- Migrasi terbaru: reorder_orders, departments+recipients (+kolom di stock_documents), user_groups(+modules,+access), confirm/cancel/reversal_of, cancel_request. `database/sql/sstock_mysql_ddl.sql` sudah KETINGGALAN (hanya sampai `add_kind_to_units`); migrasi tetap sumber kebenaran, regenerasi bila perlu.
- Pembuat dokumen yang sama masih boleh menyetujui penyesuaian (belum ada pemisahan tugas). Supervisor yang menekan Cancel tidak perlu persetujuan orang lain.
- Tombol Simpan pada modul berakses RO masih tampil (server menolak dengan pesan); menyembunyikannya belum dikerjakan.
